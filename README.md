# 帆船赛成绩离线对账台

码头网络不稳场景：竞赛官、仲裁、计时员离线各自改同一份成绩，回网后按对账规则合成，避免两版互相覆盖。

## 核心对账规则

- **四要素接成对账记录**：组别 × 成绩（到达段/更正段）× 抗议处罚 × 发布回执，每个组别一张对账表。
- **按字段合并**：到达数据只写到达段（冲线时间、到达用时），更正只写更正段，处罚进处罚列表；到达重传不冲掉更正与处罚。
- **净用时冲突留两版**：两人基于同一历史版本离线改出不同净用时，回网合成时两版都保留（A/B 卡片含操作人与依据），生效值暂回退分叉前基版，仲裁裁定取一版后才落地。
- **重复导入不新增修订**：同一 `opId` 幂等；同一抗议编号的补传合并进同一处罚项，秒数累加。
- **发布门禁**：同组别存在任何待复核冲突时禁止发布（竞赛官权限）；发布生成带回执号与校验和的整组名次回执。
- **版本链**：每次字段变化追加修订并快照各字段与净用时；成绩改动后原版本自动失效（含已发布旧版），重发前旧版及其当时回执在"版本链"抽屉中完整可查；新发布产生新回执。
- **越权拒绝**：到达限计时员、处罚限仲裁、更正限竞赛官/仲裁、裁定限仲裁、发布限竞赛官；越权写入直接拒绝并进审计时间线。
- **断网队列**：断网期间写入只进队列；回网逐条合并，已落地/重复项出队，被拒绝（越权、待复核阻塞、发布门禁）项留队；"只重试没落地的步骤"按 `appliedOpIds` 过滤，绝不重复执行。

## 页面

- **对账记录**：按组别的对账总表（到达/更正/处罚/净用时/回执/状态），可查每条船的版本链与旧版。
- **到达 / 更正 / 处罚**：三类写入表单，顶栏切换当前身份可演示越权拒绝。
- **复核与发布**：A/B 两版冲突裁定；组别发布门禁卡片与历史回执名次。
- **离线队列**：模拟断网/回网、回网合并、失败步骤重试、审计时间线。

数据使用 localStorage（键 `regatta-recon-v2`）持久化，顶栏可一键重置演示数据。

## 技术栈

React 19、TypeScript、Vite、Ant Design、Redux Toolkit、React Router。纯函数对账引擎在 `src/recon/engine.ts`，不依赖 DOM/Redux，可单独验证。

## 本地运行

```bash
npm install
npm run dev          # http://localhost:62024
npm run check        # 类型检查
npm run build        # 生产构建
npm run test:engine  # 16 项对账引擎规则自验证
```
